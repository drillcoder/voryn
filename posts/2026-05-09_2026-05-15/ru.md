Период: 9 мая 2026 - 15 мая 2026.

На этой неделе я продолжил доводить Voryn до состояния, в котором библиотеку можно спокойно эксплуатировать в реальном приложении.

Неделей раньше появился снимок состояния pipeline. Теперь нужно было сделать следующий шаг: не только получить объект с метриками, но и удобно отдать их наружу, подключить к мониторингу и уменьшить количество ручной настройки при запуске воркеров.

Что было сделано:

- добавил Prometheus-формат для метрик pipeline;
- добавил max lag по блокам и секундам;
- научил block source отдавать заголовки блоков без полной загрузки транзакций;
- поправил head worker после rebase и rollback;
- убрал ручной workerId из fetch worker;
- убрал ручной lockKey из reaction-воркеров;
- обновил примеры и README под новый API.

PipelineMetrics теперь умеет отдавать не только сырой snapshot, но и Prometheus text exposition format. Это значит, что приложение может просто вызвать метод, вернуть результат из своего endpoint для метрик и дальше подключить привычный стек мониторинга.

Я также добавил max lag. Раньше было видно отставание отдельных стадий: head, fetch и sequencer. Но для алертов часто нужен один общий сигнал: насколько сильно pipeline отстает в худшем месте. Поэтому появились max lag по блокам и max lag по времени.

Для расчета временного lag понадобилось получать не только номер последнего блока, но и timestamp. Поэтому block source получил отдельные методы для чтения заголовков блоков без полной загрузки блока с транзакциями и логами. Это дешевле и лучше подходит для метрик.

Отдельно усилил head worker. После rebase он теперь сразу enqueue-ит недостающие block jobs, а при гонке с rollback не продолжает enqueue по устаревшему cursor. Это небольшая на вид правка, но она закрывает неприятный класс состояний, когда одна часть pipeline уже откатилась, а другая могла продолжить работу из старой позиции.

В конце недели я упростил публичную конфигурацию. Fetch worker больше не требует вручную передавать workerId: instance id генерируется внутри. Reaction-воркеры больше не требуют lockKey: ключ строится из chainId, типа reaction и workerName. Внешний API стал короче, а вероятность ошибиться при копировании примеров стала ниже.

Примеры и README тоже пришлось обновить: из них ушли лишние параметры, которые раньше нужно было копировать руками. Это хорошо сочетается с общей целью недели - меньше ручной настройки и больше предсказуемого поведения из коробки.

Главная идея недели: Voryn должен быть не только корректным внутри, но и понятным снаружи. Если pipeline отстает или застрял, это должно быть видно быстро и без раскопок в базе.
