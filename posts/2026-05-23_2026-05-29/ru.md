Период: 23 мая 2026 - 29 мая 2026.

На этой неделе я продолжил готовить Voryn к нормальному multi-chain запуску.

После перехода на нормализованное хранилище следующим важным слоем стала эксплуатация. Библиотека должна предсказуемо работать не только с одной сетью, но и с несколькими: собирать метрики, валидировать источники данных, проверять PostgreSQL-схему и не ломаться на долгом retention.

Что было сделано:

- добавил multi-chain PipelineMetrics;
- сделал единый Prometheus-вывод по всем настроенным сетям;
- научил EthersBlockSource определять chainId из provider;
- упростил runtime options и примеры запуска;
- добавил GitHub Actions CI;
- обновил тестовые команды и live RPC skip;
- усилил PostgreSQL schema validation;
- перевел retention purge на ограниченные диапазоны.

Главная часть недели - multi-chain метрики. Раньше metrics-конфиг был завязан на одну сеть. Теперь PipelineMetrics принимает список chains и возвращает общий snapshot с состоянием по каждой сети.

Если pipeline следит за Ethereum, BNB Chain и еще несколькими EVM-сетями, не хочется поднимать отдельную метрик-систему для каждой. Удобнее иметь один entry point, который собирает состояние всех chain workers и отдает его в одном формате.

Prometheus-вывод тоже стал multi-chain. Библиотека может отдать один metrics endpoint по всем настроенным сетям. Для эксплуатации это проще: меньше ручной сборки вокруг библиотеки и меньше риска, что одна из сетей выпадет из наблюдения.

Отдельно переделал ethers source. Теперь EthersBlockSource.create получает providers и сам определяет chainId через getNetwork. Если provider уже знает сеть, библиотеке не нужно просить указать ее второй раз. При этом остались проверки на пустой список и дубликаты chainId.

На этой же неделе я упростил runtime options и примеры. Когда API растет, конфигурация легко становится слишком вложенной, поэтому я старался оставить настройки ближе к тому, как ими реально будут пользоваться.

Плюс появился GitHub Actions CI. Изменения начали автоматически проходить сборку и тесты не только локально. Вместе с этим обновил test scripts и сделал live RPC тесты удобнее пропускать в средах без доступа к реальным RPC.

Еще один практичный блок - PostgreSQL schema validation. Раньше проверка в основном смотрела, что нужные таблицы существуют. Теперь она проверяет структуру точнее: колонки, типы, nullable, primary keys и важные индексы. Ошибка схемы должна всплывать сразу, а не превращаться в странное поведение воркеров позже.

Retention тоже стал аккуратнее. Вместо удаления “всего до блока” сервис сначала находит oldest block и чистит данные ограниченным диапазоном. Это лучше совпадает с реальным состоянием storage и делает purge более контролируемым.

Главная идея недели: Voryn начал переходить от “pipeline работает” к “pipeline можно нормально запускать и наблюдать в multi-chain окружении”.
